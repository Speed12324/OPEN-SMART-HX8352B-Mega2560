# Полное техническое описание рабочего решения

## 1. Назначение

Настройка MCUFRIEND_kbv для OPEN-SMART HX8352B на Arduino Mega 2560. Проверка на оборудовании: 2026-11-28.

## 2. Оборудование и границы проверки

- Arduino-совместимая синяя Mega 2560, микроконтроллер ATmega2560.
- USB-мост CH340: VID `1A86`, PID `7523`; в эксперименте порт `COM3`.
- Красный шилд OPEN-SMART TFT LCD Shield, надпись `Driver IC: HX8352B`.
- 8-битная параллельная шина; это не SPI-подключение самого LCD.
- Контроллер ответил ID `0x0065`.
- Размер, заданный драйвером: 240 × 400 в портретном режиме.
- Цветные полосы и текст проверены визуально.

Маркировка HX8352B прочитана на плате, а не на открытом кристалле контроллера.
Измерение напряжений и прозвонка платы не проводились. Сенсор, SD-карта,
температурный датчик, другие ориентации и другие платы не проверялись.
Успех получен **без физического изменения подключения**.

## 3. Четыре обязательные настройки и подтверждение исходниками

1. `utility/mcufriend_shield.h`: `#define USE_SPECIAL`.
   Строки 16–22 подключают специальный драйвер распиновки и обходят обычный.
2. `utility/mcufriend_special.h`: `#define USE_OPENSMART_SHIELD_PINOUT_MEGA`.
   Ветка строк 457–512 выбирается именно для ATmega2560 и OPEN-SMART.
3. `MCUFRIEND_kbv.cpp`: `#define SUPPORT_8352B`.
   Строки 1868–1933 включают таблицу HX8352-B: питание, гамма, RGB565,
   включение отображения и размеры.
4. В скетче: **`tft.begin(0x0065)`**.
   Строка 1869 — `case 0x0065`, а не `case 0x8352`.
   `begin()` выполняет `switch (_lcd_ID = ID)`; для неизвестного ID в конце
   функции устанавливается нулевая ширина.

Название микросхемы и идентификатор выбора драйвера — не одно и то же.
В первом эксперименте `begin(0x8352)` оставил белый экран. Замена на `0x0065`
привела к цветным полосам и тексту. Само сообщение Serial «Color bars drawn»
не доказывает отображение: в неудачном тесте оно тоже печаталось.
Подсветка также может работать без корректной инициализации матрицы.

Патч относительно v3.0.0:
`patches/mcufriend-opensmart-mega.patch`.
Оригинальные исходники до изменений: `docs/source-snapshots/`.
Все файлы MCUFRIEND сверены с коммитом
`9fa56e527a88cf7e0c458dae99862ba43b213829` после нормализации CRLF/LF.
Значимые изменения — ровно три включённых макроса.

## 4. Точная распиновка, выведенная из программы

| Сигнал LCD | Порт ATmega2560 | Вывод Mega |
|---|---|---|
| D0 | PH5 | D8 |
| D1 | PH6 | D9 |
| D2 | PB4 | D10 |
| D3 | PB5 | D11 |
| D4 | PG5 | D4 |
| D5 | PB7 | D13 |
| D6 | PH3 | D6 |
| D7 | PH4 | D7 |
| RD | PF0 | A0 / D54 |
| WR | PF1 | A1 / D55 |
| RS / CD | PF2 | A2 / D56 |
| CS | PF3 | A3 / D57 |
| RESET, только программный макрос | PF1 | A1 / D55, фиктивное совпадение с WR |

В библиотеке явно написано `RESET_PIN 1 // n/a. so mimic WR_PIN`.
Это **не инструкция соединить физический RESET с WR**. Фактическая цепь
сброса платы отдельно не исследована.

D0/D1 и D6/D7 получены из масок и сдвигов PORTH; D2/D3/D5 — из PORTB;
D4 — из PORTG. Обратная функция `read_8()` использует те же соответствия.
Номера Arduino сверены с `variants/mega/pins_arduino.h` сохранённого Core 1.8.8.
Полные формулы приведены в `PINOUT.md`.
Питание и вспомогательные устройства не определяются этой LCD-веткой;
их нельзя достоверно восстановить лишь по приведённым маскам.

## 6. Восстановление Windows

1. Клонировать репозиторий и выбрать тег `v1.0.0`.
2. Скачать `windows-environment-v1.0.0.zip` из релиза.
3. Проверить SHA-256 архива по приложенному манифесту релиза.
4. Распаковать в корень репозитория: должен появиться каталог `vendor`.
5. Проверить `python scripts/verify.py` и `python scripts/verify.py --vendor`.
6. Собрать:
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -VerboseBuild
   ```
7. Результат: `.build/output/color_test.ino.hex`.

Ожидаемая SHA-256:
```
5c606f44398f1e92de6aa939ce354e2dd6326a18caf083ca3bc50c6788f7d964
```

Это сумма самого Intel HEX-файла, 45304 байта. Программа занимает 16100 байт,
глобальные переменные — 508 байт. HEX содержит адреса и контрольные суммы строк,
поэтому размер текстового файла больше размера программы.

Сборка ничего не загружает на плату. Для загрузки прошивки используется отдельная команда:
```powershell
powershell -ExecutionPolicy Bypass -File scripts/upload.ps1 -Port COM3 -ConfirmUpload
```
Скрипт без `-ConfirmUpload` отказывается работать. Загружается сохранённый рабочий
HEX. Нужен исправный совместимый загрузчик Mega; это не образ замены загрузчика.
На другом ПК номер порта может быть иным; при необходимости нужен драйвер CH340.

Сохранён Windows-инструментарий; Linux-скрипт требует CLI 1.5.1 и установки
Core 1.8.8 в отдельный `.state/linux-data`. Linux на реальном хосте не проверялся.
Точные официальные URL и суммы инструментов: `TOOL-DOWNLOADS.json`.

## 7. Результаты диагностики

1. Белый светящийся экран, без полезного изображения.
2. По фотографиям прочитаны OPEN-SMART, HX8352B, Mega 2560.
3. В документации MCUFRIEND найдены особая распиновка и нужные макросы.
4. В установленной библиотеке все три параметра были закомментированы.
5. Создана отдельная копия библиотеки; перед тестом сохранены Flash и EEPROM.
6. Первый тест с `0x8352` не дал изображения.
7. В Serial считан ID `0x65`.
8. Исходники показали соответствующую ветку `case 0x0065`.
9. После исправления ID тест успешно загружен.
10. Через веб-камеру подтверждены цветные полосы и читаемые надписи.

## 8. Симптомы и проверка

| Симптом | Возможная причина | Проверка / статус |
|---|---|---|
| Белый экран при подсветке | Неправильный ID | `0x8352` не сработал; `0x0065` сработал |
| Белый экран | Драйвер выключен при компиляции | Проверить SUPPORT_8352B; исходно был выключен |
| Белый экран/мусор | Не та распиновка | Проверить оба макроса special и реальный путь библиотеки |
| ID 0xFFFF/0x0000 | Питание, контакты, RD, шина | Гипотеза: безопасно измерить/проверить; здесь не наблюдалось |
| Serial пишет об отрисовке, LCD белый | Код выполняется, LCD не инициализирован | Подтверждено первым тестом; проверять реальное изображение |
| Изображение повёрнуто | Ориентация программы/устройства | Проверена только rotation 0 |
| Не работает после добавления устройств | Конфликт выводов/зависимостей | Гипотеза; сравнить с неизменённым архивом |

Влияние каждого макроса по отдельности аппаратно не изолировалось.
Назначение доказано исходниками; аппаратно проверена рабочая комбинация.
Не перебирайте случайные выходные уровни GPIO: возможен конфликт драйверов шины.
